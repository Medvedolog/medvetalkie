# MedveTalkie

**Открытая экспериментальная Bluetooth-переговорка и аудиоцентр для Linux-одноплатников.**

**Статус:** ранняя разработка. Двухсторонняя речь двух HFP-гарнитур на Orange Pi Zero 3 пока не подтверждена; проект нельзя считать готовым средством связи.

Идея: Orange Pi Zero 3 (H618, 1 ГБ ОЗУ), Armbian без рабочего стола, две *произвольные совместимые* Bluetooth Classic-гарнитуры с микрофонами, BlueZ и PipeWire, локальный IPS-экран, кнопки, лёгкая веб-панель. Позднее — Android-мост, FM через съёмный ATS Mini V4, интернет-радио и игры по HDMI.

## Решения по архитектуре

- **C11**; три отдельных процесса: `medvetalkied` (режимы, настройки, API, CivetWeb), `medvetalkie-bt` (BlueZ/HFP) и `medvetalkie-ui` (LVGL, SPI/HDMI/GPIO).
- **BlueZ, PipeWire, WirePlumber** — штатные службы Linux. Реальные PCM-потоки не проходят через HTTP и управляющий демон.
- **IPC по Unix-сокетам**, команды с ID и асинхронными результатами. Конфигурация SQLite; секреты сопряжения остаются у BlueZ.
- Контроллеры определяются по устойчивым признакам, не по `hci0` или номеру USB-шины.
- **Два независимых HFP/SCO-канала** — обязательный критерий качества. Если встроенный AW859A не поддерживает два канала, использовать два контроллера.
- **A2DP** в одиночном режиме — качественное стерео без микрофона; Android-мост звонков пока экспериментальный.
- Wi-Fi STA 5 ГГц для раздачи Android и интернет-радио; AP для настройки включается с экрана, с новым паролем и Wi-Fi QR-кодом.
- Дисплей 2” ST7789 320×240 едет позднее; до его прибытия отлаживаем UI через HDMI/симулятор.
- Патчи `opiz3-wlan-backport` рассматриваем для адаптации после проверки версии ядра Armbian.

## Что реально готово

Только архитектурная документация и **собираемый каркас процессов** — без реализованных HFP, веб-сервера, аудиомаршрутизации и LVGL. Статус функций не завышаем.

## Сборка каркаса

```sh
sudo apt install build-essential cmake
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
ctest --test-dir build --output-on-failure
```
